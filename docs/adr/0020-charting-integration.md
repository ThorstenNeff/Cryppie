# ADR-0020 — Charting-Integration (PRD-04)

- **Status:** **Proposed** (2026-06-19) — die bei PRD-04-Scheduling fällige Q1-Charting-Entscheidung (INDEX-reserviert). INDEX/Accept = PO. Baut auf [[0025]] (`:market` Money/Pricing-Foundation + `MarketDataApi`), der `expect/actual MarketChart`-Web-Seam (`:feature:market`, KAN-131) und [[0012]] (Adaptive Layouts).
- **Kontext:** `:feature:market` (KAN-131) rendert heute einen **Compose-Canvas-Linechart** über einen `expect/actual MarketChart(points, modifier)`-**Seam** (alle 5 Targets: android/ios/jvm/js/wasmJs; Web-Actual = dokumentierter Swap-Punkt). Der Daten-Layer `:market` (`MarketDataApi`) liefert bereits **OHLC-`Candle`s** (decimal-String, FR-6) + `priceHistory` + `spotPrices`. PRD-04 fragt: **wie weit muss das Charting für GA gehen** (Linechart? Candlesticks? Indikatoren/Drawing?) und **mit welcher Technologie** — angesichts KMP/Compose-MP über 5 Targets, wo „WebView überall" teuer ist (Android-WebView/iOS-WKWebView ok, aber **Desktop = JCEF** [schwere Chromium-Dep] und **Web = Compose-JS/DOM-Interop** [Chart-DOM neben dem Compose-Canvas]).
- **Optionen:**
  1. **Compose-Canvas (nativ, der jetzige Pfad):** reines Kotlin/Compose, läuft uniform auf allen 5 Targets über den Seam — **kein WebView, kein JS-Bundle, kein JCEF**. Konsistentes Theming/RTL/Perf, kleinster Footprint, keine Lizenz/Attribution. Linechart steht; **Candlesticks + einfache Indikatoren (MA) sind in Canvas gut machbar**; Pro-Indikatoren/Drawing-Tools wären Eigenbau.
  2. **TradingView Advanced Charts** (frei/self-hosted, JS-Lib im WebView, **UDF-Datafeed**): Pro-Charting (Candlesticks, ~100 Indikatoren, Drawing). Kosten: WebView je Target (Desktop-JCEF + Web-Interop teuer), JS-Bundle hosten, UDF-Bridge, **Lizenz-/Attributions-Auflagen** (Antrag + Terms).
  3. **Lightweight Charts** (TradingView OSS, Apache-2.0): kleine JS-Lib, Candlesticks + Basics, **keine** eingebauten Indikatoren/Drawing. Ebenfalls WebView/JS-basiert (gleiche 5-Target-Kosten), aber simple Lizenz.
- **Entscheidung:**
  - **GA = Compose-Canvas, hochgezogen auf Candlesticks** (Option 1). Der bestehende `MarketChart`-Seam rendert nativ aus `MarketDataApi.candles` (OHLC) — Candlestick-Body/Wick + Achsen + Crosshair + Range-Auswahl. Plus 1–2 Basis-Overlays (z. B. gleitender Durchschnitt) falls GA-Scope. **Kein WebView/JCEF/JS-Interop für GA.** Begründung: der Seam ist bereits unser strategischer Hebel (per-Target-Renderer-Wahl); Candlesticks decken den Kern-Bedarf; Footprint/Theming/RTL/Offline bleiben sauber; keine Lizenz-/Cross-Platform-WebView-Last für das Erst-Release.
  - **Rich-Pfad = TradingView Advanced Charts, als Post-GA-Fast-Follow** (Option 2), **eingehängt über den Seam — nur dort, wo es sich lohnt:** Mobile (Android-WebView / iOS-WKWebView) + Web (nativer JS, der `MarketChart`-Web-Actual). **Desktop bleibt Compose-Canvas** (kein JCEF). Gespeist via **UDF-Datafeed-Adapter auf `MarketDataApi`**. Aktiviert nur, wenn Pro-Indikatoren/Drawing priorisiert werden — der Seam macht das zum per-Target-Opt-in ohne Caller-Änderung.
  - **Lightweight Charts: verworfen.** Sein Hauptvorteil (Candlesticks) deckt Compose-Canvas **nativ** ab; sein Nachteil (WebView/JS-Interop über 5 Targets) bleibt. Kein Mehrwert ggü. „Canvas jetzt / Advanced Charts wenn Pro nötig".
- **WebView-Strategie je Target (für den Rich-Fast-Follow, über den Seam):** Android = `WebView`, iOS = `WKWebView`, **Web (js/wasm) = nativer JS** (der Web-Actual hängt die JS-Lib in den DOM — kein WebView), **Desktop = KEIN JCEF → Compose-Canvas-Actual behalten.** So zahlt nur, wer Rich braucht (mobile/web); Desktop + GA bleiben Canvas-leichtgewichtig.
- **Datafeed-Mapping:** Compose-Canvas konsumiert `MarketDataApi.candles(asset, interval, range)` direkt (keine UDF nötig). Für den Rich-Pfad: ein **UDF-Datafeed-Adapter** bridged die JS-Lib (config/symbols/history) auf `MarketDataApi` (über die WebView-JS-Bridge bzw. einen kleinen lokalen Shim): `Candle{openEpochSeconds,o,h,l,c,v}` → UDF-Bars `{t,o,h,l,c,v}` (decimal-String → Number erst am Render-Rand, FR-6 bleibt im Daten-Layer). **Degrade/Stale (FR-4):** `MarketException`/leere Serie → der Chart zeigt einen Degrade-/Empty-State statt Crash; Stale-Marker analog `SpotPrice`-TTL.
- **Staging:**
  - **GA-Scope:** Compose-Canvas — Candlesticks + Range (1D/1W/1M/1Y bereits gemappt) + Crosshair + Price/Δ-Header (steht). MVP-Linechart ist live (KAN-131).
  - **Fast-Follow (post-GA, wenn Pro-Charting gescheduled):** TradingView Advanced Charts (UDF→`MarketDataApi`) über den Seam auf Mobile-WebView + Web-JS; Desktop = Canvas. Eigene Story.
- **Konsequenzen:**
  - GA ohne WebView/JCEF/JS-Interop-Risiko; der Seam bleibt der saubere Erweiterungspunkt (Rich = per-Target-Opt-in, null Caller-Impact).
  - Candlestick-Canvas ist Eigenbau (Body/Wick/Achsen) — bounded; Pro-Indikatoren/Drawing bleiben dem Rich-Fast-Follow.
  - Bei Advanced Charts später: Lizenz-Antrag/Attribution + WebView-Bundle/UDF-Bridge — als eigene ADR-Ergänzung/Story bewerten, bevor aktiviert.
  - FR-6 (decimal/no-float) gewahrt: numerische Konversion nur am Render-/Pixel-Rand, nie im Daten-Layer.
