# ADR-0027 — `NetworkEnvironment`: Runtime-Network-Switching-Foundation (PRD-09)

- **Status:** **Accepted** (2026-06-23, PRD-09 / KAN-172 — PO-ratifiziert) — Dev-2-Foundation, Critical Path (entsperrt Dev-1-UI + Backend-Wiring). Baut auf der Recon (`.scratch/phase-1-mvp/09-network-switching/RECON.md`, file:line-verifiziert) + `docs/testnet-config.md`. Ergänzt [[0021]] (Key-Proxy), [[0024]] (AA/Session-Keys), [[0005]] (non-custodial). Erwartet PO-Ratifizierung.
- **Kontext:** Die App ist **mainnet-only mit hartcodierten Konstanten** — es gibt **kein** Build-Flavor und **keinen** Runtime-Toggle. Die Chain-Konfiguration ist über ~12 Stellen verstreut (Recon §2): die **Network-Slugs sind 4× dupliziert** (3 Client-Maps in `:rpc` + die `:server`-`DEFAULT_NETWORKS`-Allowlist, letztere mainnet-only + nicht env-overridable), **zwei Chain-Gates** (`SmartSessionEnableDigest.SUPPORTED_CHAIN_IDS` hart fail-closed + `AlchemyNetworks.supportedChainIds` weich), per-chain-Adressen (`universalRouter`, QuoterV2, DCA-Router), CREATE2-uniforme AA-Adressen, `TokenCatalog`, Market-/Pricing-Maps und **~37 bare `1L`/`8453L`-Literale** über ~14 Dateien. PRD-09 will **Runtime-Network-Switching** (Mainnet ⇄ Testnet: Base Sepolia `84532` / Sepolia `11155111`) als **vollwertiges Production-Feature (Scope-B, User-gepinnt 2026-06-23)** — jeder End-User schaltet in den Settings. Kernrisiko (Recon §3): **kein Fund-Leak** (die Krypto ist chain-gebunden — Sessions tragen `chainId`, die SCA-Adresse ist chain-unabhängig, falsche-Chain-Ops reverten), wohl aber **stale/mixed DISPLAY** — In-Memory-VM-Caches + Session-Listen müssen beim Switch zurückgesetzt/gefiltert werden.
- **Entscheidung:**
  - **`NetworkEnvironment` (Single-Source je Env, in `:evm`):** ein `enum NetworkEnvironment { MAINNET, TESTNET }`, jeweils mit einem `NetworkProfile`: aktive `chainIds`, per-chain `ChainProfile` (chainId · Alchemy-Slug · `universalRouter` · `quoterV2` · `dcaRouter`), die env-weit **CREATE2-uniformen** AA-Adressen (EntryPoint/Kernel-7702/SmartSessions/OwnableValidator/SpendingLimits/TimeFrame/Permit2 — Wert konstant, aber per-env **gepinnt** für das Boot-Address-Gate) und die **Backend-URLs per-Env** (proxy/auth/user-service/aa-trigger). `:evm` ist das **niedrigste gemeinsame Modul** (`:rpc`→evm, `:walletcore`→rpc→evm, `:market`→rpc→evm, `:aa`/`:send`/`:portfolio`→evm) — alle Konsumenten sehen es ohne neue Modul-Kante.
  - **`ActiveNetworkStore` (reaktiv + persistiert):** exponiert den aktiven Env als **`StateFlow<NetworkEnvironment>`** (observable — Dev-1-Contract 2026-06-23: das Shell-Scaffold keyt auf den Flow, `key(activeEnv){ WalletShell() }` → Switch ⇒ Flow-Update ⇒ VM/DI-Graph-Neuerzeugung = **Soft-Relaunch ohne Per-VM-Reload-Verdrahtung**) + `switch(env)`. Persistenz über einen **injizierten `NetworkPreferenceStore`-Port** (Interface in `:evm`; plattform-`actual` [SharedPreferences/NSUserDefaults/File] im App-Layer) — `:evm` bleibt rein + testbar (Fake-Port).
  - **Switch = Soft-Relaunch/State-Reset:** der Switch persistiert + emittiert; der Shell-Key-Wechsel reißt den VM/DI-Graph ab + baut ihn env-gebunden neu auf. Kein Fund-Leak (Krypto chain-gebunden), aber **garantiert** kein stale Display. Aktive Sessions laufen **weiter** auf ihrem Netz (nicht abgebrochen) — die Warnung informiert, blockt/revoked nicht.
  - **Backend net-param + `AA_ALLOW_TESTNET`-Host-Split:** das Backend läuft multi-chain in **einem** Deployment (net-param, `chainCtxFor`/`CHAINS`), testnet-gated durch `AA_ALLOW_TESTNET` + Boot-Address-Gate. Der **prod Money-Path-Host bleibt `AA_ALLOW_TESTNET=0` (mainnet-only)**; ein **separater Testnet-Host** läuft `AA_ALLOW_TESTNET=1`. Die App **routet per-Env** über die `NetworkEnvironment`-Backend-URL → der prod-Host kann nie auf Testnet routen (der letzte verbleibende Floor unter Scope-B).
  - **`:server`-Allowlist env-driven:** `ProxyConfig.DEFAULT_NETWORKS` wird aus `ALLOWED_NETWORKS` (env) gelesen (Default = mainnet-Slugs); der Testnet-Host setzt `eth-sepolia,base-sepolia`. So bleibt der `:server` entkoppelt (kein KMP-Import), die App spricht ihn nur über die per-Env-`PROXY_BASE_URL` an.
  - **Konsolidierung:** die 4× Slugs → eine Quelle (die `:rpc`-Maps + `:evm`-Gates lesen aus der Registry); `TokenCatalog`/Market-Maps/WETH-native werden env-parametrisiert (sie mappen schon per-chainId — die aktiven chainIds kommen aus dem Store); die ~37 bare Literale werden in benannte Registry-Lookups gefaltet.
- **Konsequenzen:**
  - **Mainnet byte-identisch (harte AK):** die Registry liefert für MAINNET exakt die heutigen Werte (Slugs/Adressen/Gates) → alle bestehenden `:evm`/byte-pin-Tests + die Verifier-Familie bleiben **regression-grün**. Der Refactor ist „Konstante → Registry-Lookup mit gleichem Wert", kein Verhaltenswechsel.
  - **Testnet hinter dem Env:** `84532`/`11155111` sind nur über `NetworkEnvironment.TESTNET` erreichbar; die Testnet-spezifischen Adressen (UR/QuoterV2/USDC) trägt das Testnet-Profil (aus offiziellen Quellen, nicht geraten — Platzhalter bis befüllt).
  - **Safety-Triade unter Scope-B:** da der Backend-`AA_ALLOW_TESTNET=0`-Floor als End-User-Schranke entfällt (Production-User erreichen Testnet), ruht die Sicherheit auf (1) dem app-shell-weiten **non-disableable TESTNET-Indikator**, (2) den **Switch-Warnungen**, (3) der **per-Net-State-Isolation** — alle Dev-1/UX (KAN-172-Folge-Stories). Der einzige verbleibende Host-Floor: der Mainnet-Money-Path-Host bleibt mainnet-only, die App routet Testnet auf den dedizierten Host.
  - **CREATE2-uniforme AA-Adressen:** kein per-env-*Wert*, aber das **per-Net-Boot-Address-Gate** (Backend `verifyAddressesOnChain`) bleibt nötig — gleiche Adresse nur, *wenn* auf dem Ziel-Testnet deployed.
- **Alternativen (verworfen / aufgeschoben):** **Build-Flavor** (verworfen — Scope-B braucht Runtime-Switch ohne Rebuild); **separates `:network`-Modul unter `:evm`** (aufgeschoben — die AA-Adress-Konstanten aus `:evm` herauszuziehen riskiert die byte-pin-Regression; `:evm` ist ohnehin das niedrigste gemeinsame Modul); **per-Env-Backend-Deployment** (verworfen — net-param genügt, der Host-Split liefert den Safety-Floor); **synchrones get/set im Store** (verworfen — Dev-1s Soft-Relaunch braucht den observablen `StateFlow`).
